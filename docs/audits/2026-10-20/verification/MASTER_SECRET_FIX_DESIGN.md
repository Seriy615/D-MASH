# Master/emergency secret: конечный план исправления

20 октября 2026. Source `9446c22f27309131456942870971d477f6f2358f`. **READ-ONLY review + synthetic mechanism repro; исправления приложения ещё не внесены.** Обязательное условие: сохранить DeviceRoot, Account identities/history и encrypted storage; ordinary unlock failure никогда не разрешает reset. Это ограниченный следующий implementation slice для общей библиотеки Android/Desktop, не ещё один этап перепроектирования всего приложения.

## Выбранное исправление, без downgrade

1. Выделить небольшой общий `LocalCredentialService` и crypto-port, используемые calculator, Core settings, emergency wipe и biometric repair. UI больше не читает/пишет `sys_m/sys_w` для авторизации. Hardened проверка не может сохранить дешёвый PIN-match фильтр: ограничить её valid 4–10 digit candidate и намеренным submit; выполнять в worker, не более одного KDF на installation одновременно, с bounded retry budget/cancel. Для decoy calculator отдельно измерить responsiveness; не возвращать fast verifier ради задержки. Все crypto-sensitive операции ждут реально завершённый bundled Argon2/WASM loader и валидируют экспорт enum; unavailable/error → fail closed с сохранением данных. **PBKDF2/fast-hash fallback не вводить.** Android/Desktop используют одинаковые versioned profiles/test vectors.
2. Master проверяется успешным authenticated unwrap **существующего** root, без отдельного master verifier. Новый формат явно хранит KDF profile и параметры: `argon2id-v19`, type=2, time=3, mem=65536 KiB, parallelism=1, hashLen=32; AES-256-GCM wrap остаётся стандартным. Старый mislabeled v1 читается как подтверждённый legacy Argon2d profile type=0 с прежними параметрами/encoding salt; old bytes не меняются до успешного unwrap. Если provenance старого импортированного record допускает id, bounded d/id compatibility проба разрешает только успешный GCM tag, не создаёт root и не ослабляет new profile. Success сохраняет профиль, которым действительно открыты старые bytes.
3. Wipe-код получает отдельный salted Argon2id verifier. Для **совместимой миграции без знания старого wipe PIN** использовать явный профиль `wipe-sha256-prehash-argon2id-v1`: pass = lowercase hex SHA-256(candidate), случайный salt ≥16 bytes, Argon2id с теми же cost bounds; Точное salt input: UTF-8 строка `dmash/local-wipe/v1|` + canonical base64 случайных 16 bytes; random salt/profile/version сохраняются и проверяются. Это отдельный namespace от root wrap. Имеющийся `sys_w` является ровно таким prehash и может быть преобразован в новый verifier после доказанного master unlock. SHA-256 промежуточный результат только в RAM; в storage остаётся только salted expensive output. Это проверяемая композиция существующих примитивов, не новый KDF. Один verifier на wipe, ограниченные параметры/длина input и bytewise сравнение.
4. Root wrap, credential profile/version/revision, wipe verifier, setup phase и migration marker сохраняются **одним record/одной IDB transaction**. Не пытаться сделать атомарным root IDB + localStorage. `sys_configured` становится только необязательным hint; startup читает canonical record. Удаление legacy hashes выполняется после подтверждённого commit; если localStorage cleanup не удался, помечается `MIGRATION_CLEANUP_REQUIRED`, повторяется при startup и новая защита не объявляется завершённой. Не хранить plaintext PIN в pending journal/backup/logs. Защищённый backup не содержит незашифрованную копию старых hashes.
5. Migration: ввод прежнего master → legacy cryptographic unwrap → подготовка нового wrap **того же root** и hardened wipe verifier → проверка нового wrap на том же root/identity в RAM → CAS commit revision → legacy hash cleanup. До commit старый wrap рабочий; после commit только новый canonical profile. Если `sys_m` не совпадает, но root открылся, root является authority, stale hash не блокирует доступ. Account derivation остаётся на прежнем проверенном профиле: отдельная Account migration требует сохранённых identity pins и собственного review; её не смешивать с этим исправлением.

## Setup/change/recovery/wipe

| Сценарий | Обязательное поведение |
|---|---|
| Fresh setup | Explicit create разрешён только после inventory, подтверждающего отсутствие root/legacy vault/registry и pending wipe. Создать pending-setup canonical record с защищённым root; после выбора distinct master/wipe завершить credentials transaction. Reload pending setup требует master unwrap и продолжает настройку; не генерирует другой root |
| Legacy configured UI, root ещё отсутствует | Отсутствие root не доказательство fresh install. При существующих старых данных → explicit legacy migration/recovery. Только доказанно пустая installation может завершить старую setup после ввода legacy PIN; дешёвый старый hash не используется как proof владения существующим encrypted vault |
| Master + wipe change | Текущий master доказывается unwrap; новые параметры готовятся в RAM; atomic CAS обновляет wrap+wipe+revision. Concurrent biometric/material writes merge-ятся по актуальному record, сменившийся credential revision даёт conflict. Старый root/identity не меняются; нет окна «новый wrap/старый verifier» |
| Отдельный wipe change | Требует текущую локальную авторизацию unlocked root/повтор master согласно settings, те же PIN bounds и отдельный Argon2id verifier. `Core.changePinFlow` больше не пишет localStorage |
| Legacy master/wipe совпадают | Сохранить master доступ; wipe collision отключить с явным предложением выбрать distinct wipe PIN. Не превращать обычный master unlock в wipe |
| Corrupt wrap / неверный PIN | Никаких delete/create/recovery reset. Сохранить record; показать unlock/recovery error. Legacy Account-passphrase recovery — только explicit существующий `migrateLegacyAccountPassphrase` с успешным old unwrap и rewrap того же root |
| Biometric repair повреждённого wrap | Fresh successful WebAuthn unwrap доказывает тот же root. Отдельное явное действие repair с подтверждением нового master заменяет повреждённый wrap через canonical transaction; не выдавать SHA-256 `sys_m` за достаточное cryptographic proof. Без recoverable root — отказ, не новая identity |
| Emergency `0010<master>=` | Central service проверяет существующий root без запуска Node/Account; invalid suffix/cancel → zero destructive calls. Corrupt root не стирается по совпадению legacy hash. Публичную последовательность сохранить; `1020` либо документированная совместимость, либо явно удалённый legacy alias с тестом |
| Wipe-code / explicit full wipe | Только authenticated соответствующий code либо отдельное осознанное full-reset действие. Один deletion coordinator вместо трёх независимых helpers. Durable `WIPE_PENDING` marker вне удаляемых DB, остановка workers/connections, затем ожидаемые deletion results. Blocked/error/timeouts → incomplete и retry; marker запрещает new setup до фактического завершения. Удаление DB не атомарно между databases; это resumable destructive operation, а не обещание rollback |

## Cancellation и crash consistency

Каждая async credential operation имеет generation/session token и expected credential revision. AC/back/cancel/root-lock/новая попытка инвалидируют token и очищают pending secret fields; проверка после **каждого** await и перед commit/show_gate/delete. Сейчас unlockGeneration проверяется до `Core.unlockDevice`, но не после него; поздний unwrap не должен вновь публиковать unlocked root/gate после lock. Unlock должен разделять prepare и publish: stale completion уничтожает подготовленный root и не делает network startup. String PIN нельзя гарантированно занулить в JS; ссылки убираются сразу, byte buffers zero-ятся, секреты не логируются.

Write lock/CAS и abort guard распространяются на loaded v50 repair, credential change и wipe. После commit crash не «откатывает» revision; UI success читается из canonical record. После незавершённого wipe next launch возобновляет cleanup либо сообщает blocked, не считает отсутствие root разрешением fresh identity. Другая вкладка/процесс не продолжает работать с удаляемой generation.

## Конечные проверки перед интеграцией

- Real bundled WASM vectors: implicit legacy d / explicit d/id; production legacy wrap → migrate → тот же root/DeviceID/materials; старый и новый master, неверный PIN, corrupted tag/record, недоступный Argon2. Отдельно проверить неизменность Account signing/box/history pins.
- Synthetic crash injection: до/после root commit, quota error, legacy cleanup failure, параллельный biometric write/credential change, lock/cancel во время каждого KDF/unwrap/commit, restart и повтор одной операции.
- Все actual loaded callers используют central service; отсутствие новых fast `sys_m/sys_w`, сохранённых prehash/plaintext PIN и silent fallback. Обновить устаревшие `calculator_secret_gate.test.js` и `device_root.test.js`: они сейчас содержат assertions/comments про fresh identity после recovery, противоречащие действующему запрету.
- Browser clicks на synthetic profiles: fresh setup, expression-derived PIN, invalid/valid master, legacy migration, master/wipe change с cancel/back/error, biometric cancel/repair, root lock при in-flight unlock, reload/history preservation; неверные `0010`/`1020`/wipe suffix никогда не удаляют sentinel. Correct-code/full wipe, blocked second tab и interrupted deletion — **только disposable profiles**, с подтверждением всех stores, а не redirect как доказательством успеха.
- Android и Desktop запускают те же vectors и lifecycle flows; physical platform biometric/background/storage checks помечаются NOT RUN до фактического запуска. UI baseline перед product changes ведёт root; этот документ не заменяет BROWSER_QA.
