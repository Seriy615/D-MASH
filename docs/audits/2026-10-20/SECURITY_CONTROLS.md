## Основание в коде и identities

[DeviceRoot](https://github.com/Seriy615/D-MASH/blob/9446c22f27309131456942870971d477f6f2358f/D-MASH%20PWA/not_messenger/js/device_root.js): `unlock` (541+) создаёт random root только при отсутствии существующего/legacy vault; `derive` (210+) использует HKDF-SHA-256, `deviceIdentity` (365+) выводит Ed25519/X25519 keys. Root и установка постоянны; неверный unlock не создаёт новую identity. [Core.boot](https://github.com/Seriy615/D-MASH/blob/9446c22f27309131456942870971d477f6f2358f/D-MASH%20PWA/not_messenger/js/core_engine.js), строки 323–390: фактический legacy Argon2d от Account identity+passphrase (enum mismatch, [actual vendor evidence](verification/actual-argon2-results.json)) → Account signing/box keys; `pub_hex` = signing + box + сохранённый installation legacy Kyber public material (имя slot не доказывает ML-KEM conformance). **Это не DeviceRoot signing/agreement public key.** Password-derived Account keys не означают, что весь bundle выводится только из пароля.

Пользователь описывает один постоянный device encryption pub, который не должен светиться сети. Не заменять его pairwise DeviceRoot identities. Фактический [обычный PRIVATE QR](https://github.com/Seriy615/D-MASH/blob/9446c22f27309131456942870971d477f6f2358f/D-MASH%20PWA/not_messenger/js/acceptance_fixes.js), строки 60+: `DMASH_PAIRING_V1` с AccountID+contribution; [managed-v4 QR](https://github.com/Seriy615/D-MASH/blob/9446c22f27309131456942870971d477f6f2358f/D-MASH%20PWA/not_messenger/js/public_account_orchestrator_v4.js), строки 50+: signed `DMASH_PAIRING_V2` с Account signing/box/KEM bundle и route certificate. Это Account/route обмен, а не доказательство уже реализованного QR из одного скрытого device pub. Требуемое отображение QR нуждается в отдельной versioned спецификации/миграции; не объявлять per-peer QR keys выбранной моделью.

[PrivateRoutesV3](https://github.com/Seriy615/D-MASH/blob/9446c22f27309131456942870971d477f6f2358f/D-MASH%20PWA/not_messenger/js/private_routes_v3.js), строки 11–49: directional authority/box keys и route locators выводятся из двух contributions, generation и A_TO_B/B_TO_A labels. A→B, B→A и A→C — отдельные **направленные routes**. Не заменять Node identity random pair IDs и не mint-ить новые случайные route IDs вместо действующего KDF. Node peer auth key, route locator/authority, Account key и локальный DeviceRoot — разные сущности. Видимый Node auth key/HELLO способен коррелировать connections отдельно от device encryption pub; route IDs сами не скрывают IP/timing.

[Core logout/panic](https://github.com/Seriy615/D-MASH/blob/9446c22f27309131456942870971d477f6f2358f/D-MASH%20PWA/not_messenger/js/core_engine.js), строки 676–817, уже различает Account logout и полный root lock. [FileRuntime](https://github.com/Seriy615/D-MASH/blob/9446c22f27309131456942870971d477f6f2358f/D-MASH%20PWA/not_messenger/js/file_runtime.js) имеет Account-bound vault/retry, managed-v4 CONTROL и предел 64 MiB; независимый opaque daemon handoff ещё не реализован. [CallSession](https://github.com/Seriy615/D-MASH/blob/9446c22f27309131456942870971d477f6f2358f/D-MASH%20PWA/not_messenger/js/call_session.js), строка 182: relay/all ICE policy не равна готовому общему privacy engine.

[UI master verifier](https://github.com/Seriy615/D-MASH/blob/9446c22f27309131456942870971d477f6f2358f/D-MASH%20PWA/not_messenger/js/ui_logic.js), строки 404–443, хранит быстрый hash `sys_m`; validators встречаются в acceptance_v50/v53/v54 и stability_fixes. Это риск offline PIN guessing, а не expert option. Исправление требует согласованной миграции verifier/wrap с backup и без reset root. ## Продуктовое поведение — НЕ РЕАЛИЗОВАНО

Обычный путь: unlock при необходимости → чат/подтверждение контакта → отправка. Все поддержанные настройки индивидуально доступны; presets только заполняют defaults. Пользователь может сохранить правила для контакта/файлов, поэтому обязательного технического диалога на каждую отправку нет. Optional per-file override не расширяет grants и не отключает криптографические проверки.

Account работает с plaintext/E2EE, формирует packet и file dependencies. Daemon единожды принимает подготовленные encrypted bytes и полностью владеет transport/retry/provider failover; он не просит Account переподписать invitation при смене storage Node. UI показывает последствия и effective policy, а не выполняет сетевой scheduler. Account receipt создаётся после Account verification; daemon хранит/повторяет уже упакованный receipt.

Presets: «Сбалансированный» предлагает разрешённые direct NAT links с relay/buffer fallback; «Через relay» запрещает direct payload, ICE candidates/checks/probes и прочие несовместимые сетевые пути; «Свой» сохраняет отдельные параметры. Изменённый preset становится «Свой», параметры остаются видимыми. Нет подходящего relay → очередь/недоступность, без скрытого direct. Relay видит свои подключения и traffic metadata; ни preset, ни decoy не обещают анонимность.

## Конкретная модель policy — НЕ РЕАЛИЗОВАНО

Запись: `{version, scope, revision, values, source, updatedAt}`. Scopes: установка/Node; локальное opaque relationship; Account; контакт; одно logical operation/file. Account хранит plaintext/UI предпочтения, Node — transport/resource. При submit контактное правило превращается в локальную `operationPolicyCapability` с owner, допустимым direction handle+generation, expiry и limits; topology/AccountID в wire не передаются. Parent policy update может сузить такую capability, но job не получает полномочия выше parent.

Эффективные разрешённые пути/сети/providers = пересечение supported protocol, Node hard limits, peer grants, Account/contact rules и явного operation override. Для quotas/max size/TTL/rates берётся минимум всех caps; для required replicas — пользовательская цель, ограниченная допустимым максимумом и ресурсным budget. Несовместимые min/max/пустое множество дают `WAITING_POLICY`/validation error с причиной. Override изменяет наследуемое предпочтение, но не обходит более строгий parent/grant. Неподдержанный toggle отображается «планируется», не как работающий control.

`setPolicy(expectedRevision, patch)` проверяет owner/scope, типы/единицы, допустимые bounds, зависимости, grants и storage feasibility; CAS предотвращает потерю параллельного изменения. В одной durable transaction сохраняет новую revision+effective policy+queue reconciliation intent. Scheduler проверяет revision **перед каждым** attempt, retransmit, connect и выдачей bytes; stale workers получают cancellation token. После crash ни старая revision, ни старый разрешённый path не продолжаются автоматически. UI различает сохранено/применяется/эффективно и показывает source ограничения.

Все строки ниже — предложенный scope; наличие таблицы не означает поддержку в коде.

| Настройка | Scope / owner | Валидация и применение к очереди |
|---|---|---|
| Direct, relay-only, разрешение IP disclosure | Node hard cap; relationship/contact/operation могут сужать; daemon | Согласие обоих peers; relay-only немедленно блокирует queued direct retries и новые bytes, отменяет probes/ICE и закрывает direct sessions. UI «применяется» до закрытия; уже раскрытый IP не отзывается |
| Providers/anchors | Node/relationship, per-file subset; daemon | Allow/deny или одобренные relationships, auth pins и grants. Новая policy запрещает новые PUT/GET к excluded provider; перенос имеющейся копии выполняется только допустимым путём. Нет такого пути → wait, не callback Account |
| Wi-Fi/mobile/roaming, upload/download rate | Node и операция; daemon | Bytes/s и сети, отдельные лимиты personal/transit/store. Network change немедленно останавливает запрещённые attempts, сохраняет durable offset |
| Transit participation | Node; daemon | On/off, queued bytes, CPU budget, rate. Off запрещает новую чужую работу; существующие leases drain/decline по объявленным bounds, без доступа к Account |
| Чужое store участие | Node; daemon | Отдельно от transit: disk cap, max object, TTL, concurrent reservations, promised/best-effort mode. Disable прекращает новые grants, старые retained objects drain до срока |
| Собственные files | Account/contact/operation preference, Node limits; daemon | Способ Auto/direct-only/buffer, размер, replicas, TTL, queued bytes, resume/retry. Direct-only не обещает offline retrieval; buffer может иметь relay-only network policy |
| Background/battery | Node platform policy | Min battery, charging-only, разрешённые сети, concurrency. OS stop/Doze показывается как suspended; исключения ОС не обходятся скрыто |
| Auto-download/consent | Account/contact; Account экспортирует opaque решение | Сохранённое правило по типу/размеру/сети; имя/MIME из непроверенной сети не выполняются. Нет blanket проверки только расширения; file integrity обязательна |
| Account auto-lock | Account/app | Отдельные inactivity/screen-off/keyguard правила; закрывает plaintext handles/ключи, не ciphertext Node queue |
| Полный DeviceRoot lock | Установка | Явное действие/отдельный timer: останавливает защищённый Node runtime/keys; не выдаётся за сохранение активного transit |
| Уведомления/preview | Account/contact + OS | Default нейтральный; содержимое только в разрешённом unlocked Account. Locked notification/wake не требует decrypt в daemon |
| Cache/history retention, export/recovery | Account или root по операции | Раздельные владельцы/сроки и encrypted/plaintext export; restore проверяет прежнюю identity, не создаёт её заново при ошибке |
| Contact revoke / Node peering revoke | Account / Node раздельно | Contact меняет E2EE доступ; Node отзывает scoped route/grant generation. A→B revoke не автоматически B→A или A→C; mutual revoke — явный выбор |

Файловые значения для первой предлагаемой buffer версии: max 64 MiB с возможностью уменьшения, TTL 1 час–7 суток, replicas/anchors 1–3, concurrency ≤2 provider uploads/job и окно ≤8 chunks. Остальные disk/rate/CPU budgets выбираются ограниченными по платформе и измеряются; бесконечное значение не принимается. Existing DataChannel chunks 32 KiB и новый buffer chunk 16 KiB — разные versioned formats. Изменение protocol upper bound не сводится к полю UI.

Уменьшение TTL/replica target действует на новые jobs по умолчанию; отдельное «применить к ожидающим» пересчитывает deadlines/availability и публикует locator generation без перепаковки Account packet. Продление не превышает существующий Account-sealed deadline: нужно новое Account-authorized job при unlock. Число достигнутых custody receipts показывается отдельно от target и verified recipient delivery.

Уменьшение store quota ниже уже принятого объёма запрещает новые reservations и создаёт drain debt. Нельзя тихо удалять retained bytes ради красивой цифры. Emergency revoke — отдельное действие с конкретными затронутыми сроками/обязательствами; в best-effort режиме early eviction разрешена только согласно выданному receipt. Retention обещает условия честного provider, не невозможность disk loss. Remote delete/revoke никогда не обещает уничтожить скачанные копии.

## Screen lock, Account logout и root lock

Screen off сам по себе меняет только выбранные display/background правила. OS keyguard выполняет **явно настроенные** Account и root lock rules; не следует автоматически приравнивать его к полному D-MASH lock. Account logout закрывает Account E2EE/plaintext access и очищает UI/preview согласно policy; Node продолжает encrypted inbox, transit и уже принятые opaque jobs. Первое извлечение attachment descriptor требует recipient Account unlock; после экспорта retrieval capability daemon может догружать ciphertext при logout. Финальное decrypt/verification ждёт Account.

Полный DeviceRoot lock закрывает Node sessions/ключи и прекращает защищённый transit; на диске остаются зашифрованные spool/jobs, восстановление после unlock проверяет expiry/policy revision. OS biometric/WebAuthn PRF может удобно unlock существующий wrap при поддержке платформы, но не заменяет Account authorization и не обещает recovery без достаточного material. Отмена, неверный PIN, потеря OS key или ошибка миграции не создают новый root/vault.

Plaintext lifetime/account lock и encrypted job lifetime независимы. Для простоты первый проект не требует background Account decrypt: locked Account только накапливает encrypted delivery. Если позже вводится unlocked background Account actor, его keys/receipt semantics и политика доступа специфицируются отдельно от daemon.

## Что остаётся обязательным и как проверять

Нельзя превратить authentication/integrity, replay checks, ownership/grants, parser bounds, AEAD/manifest verification или OS permissions в произвольные off-checkboxes. Crypto suites меняются только согласованной versioned реализацией. PoW/admission выполняет Node автоматически с bounded CPU/battery budget; уменьшение собственного бюджета не уменьшает требования peer. Decoy/calculator и convenience unlock — отдельные UX возможности, без обещания скрыть приложение от ОС/backups.

Миграция читает прежние scopes/identities/защиту, сохраняет backup и переносит policy с явной версией. Defaults новой установки не переписывают старые preferences. Изменение защиты/wrap выполняется через существующий owner и подтверждённое полномочие; routine per-send confirmation не требуется. Старые grants/queued operations проходят reconciliation; восстановление старого policy snapshot не возвращает отменённые поколения. Unsupported protocol остаётся явно unsupported.

Приёмка каждой настройки: UI action → validation/effective state → реально изменившееся поведение → restart persistence → конфликт peer/OS → cancel/error. Обязательно queued direct retry во время relay-only switch, DNS/ICE/probe/egress capture, offline background без Account, screen-off/keyguard/logout/root-lock отдельно, store drain/expiry/revoke и failed migration с сохранением identities/history. File provider failover не вызывает Account, custody не выставляет `DELIVERED`; A→B grant не работает для B→A/A→C. CPU/RAM/disk/network/battery проверять измерениями, device lifecycle — physical phone. **В этой редакции выполнена source/document review; новая реализация и UNIT/BROWSER/DEVICE проверки не выполнялись.**
