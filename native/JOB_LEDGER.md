# Native encrypted job ledger — C02 storage checkpoint

`src/job_ledger.*` implements the local persistent boundary; the subsequent C02 actor adapter now connects it to scoped local IPC and the existing routing scheduler. The network API/consumer authority is defined in [LOCAL_IPC_V1.md](LOCAL_IPC_V1.md). An authenticated owner scope must come from that adapter, never from an untrusted request parameter. This port stores opaque transport bytes and public destination metadata, not Account plaintext or Root credentials.

SQLite WAL/FULL transactions cover acceptance, scoped operation dedupe, quotas and state updates. Node-specific HKDF domains derive outer storage encryption/alias keys from the scoped Node storage key. AES256-GCM authenticates complete records and owner/policy metadata against the Node/profile/domain/id. SQL scheduling/index fields are checked against their encrypted copies when records are opened. Missing owner metadata with existing job/destination rows fails closed; wrong Node/key cannot reopen. Derived keys wipe on construction failure and close.

Owner acquisition increments an authenticated durable epoch. Mutations and `maySend` reject a stale owner. Policy revision increases atomically; `revoke` also raises the minimum transport generation before disabling writes. A revoked old boot grant cannot reopen the same retained ledger. External backup/OS anti-rollback authority remains a separate gate.

Acceptance persists its own bytes, digest, caller/destination-scoped operation alias, job handle, expiry and retention before returning. Exact retries preserve the handle even after expiry while the retention record exists; changed bytes/expiry conflict. Quotas apply globally, per owner and per destination, including retained terminal jobs. Lowering quotas preserves existing work; pruning removes only records past their declared retention horizon. Waiting for bootstrap does not consume work attempts; a trusted peer-ready event may claim that state before its stored expiry deadline. Other retries keep their normal backoff bounds. Terminal/destination retention deadlines are scheduled and pruning reclaims their quotas after the declared horizon. A claim/attempt token and durable revision fence late callbacks/cancel/retry; successful send means only TRANSPORT_SENT.

The first profile bounds64 durable owner scopes,1024 destination grants,4096 jobs/32MiB of raw opaque bytes globally (encrypted/base64/index overhead additionally bounded by record count),512 jobs/8MiB per owner and128 jobs/2MiB per destination, body≤65536 bytes, maximum20 actual attempts, seven-day maximum validity and24-hour post-expiry retention. Existing mesh recipient-box limits remain smaller and must be checked by the actual routing adapter before accepting a new job. The ledger does not itself verify certificates or local Account ownership signatures.

`native-job-ledger` tests actual SQLite transactions and child-process hard exits before/after acceptance commit, same-handle retry after lost reply, changed-content conflict, owner/destination isolation, quota/lowered-quota behavior, stale owner and boot-grant rejection, policy/cancel send fencing, wrong key/Node, wrong thread, encrypted body-at-rest, fair owner selection, offline deferral and expiry/retention. These storage tests do not themselves establish IPC authentication or delivery. Separate actual executable IPC/delivery fixtures cover the first Linux integration slice; physical power-loss durability and native platform service behavior remain separate gates.
