# Native broker control lifetime

This is the concrete contract for the separate credential service and [dmash-local-v1](../LOCAL_IPC_V1.md). `ControlJournal` implements only the durable public control metadata. The OS process supervisor, authenticated IPC and canonical credential service still require integration; the journal cannot prove daemon exit or erase another process's RAM.

The journal is bound to the existing public DeviceID and contains only version, transport generation, policy revision and phase. Explicit creation requires a live prepared Root proof and a new private file. Opening an absent/corrupt/wrong-binding journal fails instead of resetting counters or creating an identity. SQLite uses WAL/FULL and BEGIN IMMEDIATE; two processes cannot reserve the same active session. Counter arithmetic stops at the JavaScript safe-integer bound used by the existing transport bundle.

| Operation | Atomic durable transition | Required external action |
|---|---|---|
| `reserveSession(proof)` | LOCKED→ACTIVE; increase generation and policy revision | Recheck current Root proof; export same existing scoped Node materials; install them only over authenticated inherited bootstrap channel. A reservation is not an issued capability. |
| `reservePolicyRevision(g)` | ACTIVE/current generation; increase policy revision | Send validated policy with this revision; show updating until daemon confirms committed effective policy. Reserved-but-unused revisions are never reused. |
| `beginFullLock()` | ACTIVE→REVOKING; raise both floors; repeated pending calls reuse them | Send exact floors to daemon; daemon durably fences old grants and exits. If unreachable, supervisor must verify its owned child exited, not trust a reused PID. |
| `mergeStoppedDaemonFloors(expected,minG,minP)` | Exact local snapshot; merge verified remote floors by maximum; set LOCKED | Requires authenticated scoped-key binding and actual owned-child exit; never consume unauthenticated error/log values. |
| `confirmStopped(pending)` | Exact pending floors REVOKING→LOCKED; duplicate completion idempotent | Caller must hold authenticated exact-floor acknowledgement/exit proof. Journal data by itself is not such proof. |

On a user full-Root-lock request, first invalidate the broker operation epoch and dispose owned Root/Account handles. Then durably record REVOKING before sending revoke. Display LOCKING until daemon persisted the floors and acknowledged/exited, or the supervisor verified owned-child termination. Already-started OS writes cannot be recalled; after daemon fence commit no queued forbidden write may begin. If journal/daemon/exit confirmation fails, remain pending/error rather than claiming full lock. Root material remains unavailable locally. Cancel after accepted lock does not restore old authority.

A crash after journal commit but before acknowledgement leaves REVOKING. Startup must finish fencing/termination; it cannot reserve a new session meanwhile. A crash after reserving ACTIVE but before capability issue burns that reservation: enter the same revocation flow and then reserve a strictly newer generation. A broker crash can also make the daemon self-revoke on bootstrap EOF while the broker journal still says ACTIVE. If the next child rejects an old grant with STALE_FLOOR, consume its floors only over the private authenticated bootstrap channel after correct scoped-storage-key binding, verify that owned child exited, transactionally merge them against the exact unchanged journal snapshot, and reserve strictly newer counters. Do not reset the profile or Node identity. New grants exceed both journal and daemon saved floors. SQLite durability does not supply backup anti-rollback or authority for a second writer; restoring older control/daemon state needs an explicit recovery gate.

The inherited authenticated bootstrap descriptor is the **credential service lifetime lease**. Broker-service EOF makes the daemon fence writes and shut down until a new authorized session. A UI client window/activity closes its own connection, not that descriptor. Account logout clears Account plaintext/keys and its UI capabilities while leaving approved Node transport and accepted ciphertext jobs alive. Normal policy changes do not require per-send dialogues. Full Root lock revokes transport. OS-wrapped autonomous restart authority is a separate explicit policy and may contain only scoped transport keys, never PIN/full Root/Account material.

The service must enforce one worker-thread owner for a journal instance and a monotonic current-operation epoch for Root codec handles. Before network handoff, it must recheck the proof and reserved generation; a canceled reservation must never become a late grant. `BrokerService` now implements the worker/epoch coordinator and `CredentialStore` persists explicit complete-profile imports; the platform must supply the actual complete exporter, OS key provisioning and authenticated daemon supervisor. A missing encrypted Root always remains a refusal, independent of control metadata.

Required integration gates: actual daemon revoke/EOF while writes are queued; UI-process death with service/daemon continuing; broker death and fresh generation restart; policy commit before queued retransmit; crash at each lock-intent/reply boundary; Android Doze/reboot and Windows/Linux process/runtime behavior. The journal UNIT includes an abrupt `_Exit` after committed intent and independent competing process reservations. It does not substitute these runtime gates.
